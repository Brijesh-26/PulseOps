## Environment (inspected 2026-10-18)

- macOS (arm64), Python 3.12.12, `uv` 0.10.12, Docker 28.5 (Docker Desktop).
- Node.js is **not** installed on the host. By decision, all dashboard tooling runs in `node:22-alpine` containers (`make dashboard-check`).
- There are no AWS credentials and no `gh` CLI. Deployment is configuration plus manual steps.

## Local workflow

```bash
make up                         # full stack; dashboard on :5173, API on :8000
make scenarios                  # load scenarios A–E
uv run pytest -q                # needs postgres (:5433) and elasticmq (:9324) from compose
make lint typecheck dashboard-check evaluate
```

Integration tests create and migrate a dedicated `pulseops_test` database. The connection string can be changed with `PULSEOPS_TEST_DATABASE_URL`. When it is unset and Postgres is unreachable, those tests are skipped. When it *is* set, as in CI, connection failures make the tests fail.

## Milestone log (checks actually run)

- **M1. Scaffold.** uv project, settings, structured logging with redaction, middleware, health and readiness checks, queue adapters, Compose with Postgres 17 and ElasticMQ.
- **M2. Data model.**
  - 21 tables with foreign keys, unique, partial-unique and check constraints, and indexes.
  - Audit triggers and least-privilege grants.
  - Migration tested up, down and up again; `alembic check` reports no drift.
  - Append-only behaviour verified manually with psql, for both the owner and the app role.
- **M3. Ingestion.** Contract, idempotency, the 409 on reuse of an event ID with a different payload, and authentication. A concurrency test sends 16 parallel duplicates and gets exactly 1 × 202, 15 × 200, one event row and one outbox row.
- **M4. Processing.** Relay, worker, backoff, the DLQ and the incident engine. Tests cover redelivery idempotency, correlation, retry then success, dead-letter after N attempts, poison messages and relay publish retry.
- **M5. Evidence and graph.** Recursive-CTE traversal, cycle rejection, termination despite an out-of-band cycle, and full-text search.
- **M6. Investigator.**
  - Strict schema v1, the mock provider, and the Claude provider (bounded tool loop).
  - Backend validation and backend injection detection.
  - Adversarial provider tests and Claude-loop tests with a fake client. **No real Claude API call has been made.**
- **M7. Remediation.** Proposals, approval and rejection, staleness, expiry, preconditions at both stages, exactly-once execution under concurrent approval and redelivered messages, and the audit chain.
- **M8. Scenarios A–E.** YAML fixtures, loader, CLI, demo endpoint and evaluation harness.
- **M9. Dashboard.**
  - React, TypeScript and TanStack Query.
  - 10 Vitest/RTL tests; eslint, tsc and the build pass.
  - Verified against the live stack with headless Chromium (Playwright 1.64.1). Screenshots are in `docs/screenshots/`.
- **M10. Evaluation, security and CI.**
  - `python -m simulator evaluate` passes 5/5 with the mock provider.
  - pip-audit (locked dependencies) and npm audit report no known vulnerabilities, and gitleaks found no leaks (run locally on 2026-10-18).

- **M11. Deployment and docs.**

  - Docs: README, architecture, data-model, security, deployment, evaluation and ADRs.

### Issues found and fixed during the work (for the record)
- Autogenerated duplicate enum CHECK constraints were removed from the migration.
- Graph traversal ordering was not deterministic; it now sorts by depth and then key.
- Incident numbers had identity gaps from conflicting inserts; the engine now selects before inserting.
- The latency rule fired on the runtime of a *failed* run, adding irrelevant "missing information". It is now limited to latency incidents.
- Injected text copied into an execution's `error_message` was being used as support. This led to backend-side injection detection across all evidence kinds, plus a regression test with a provider that obeys an injection.
- The dashboard's CSP `<meta>` tag blocked the Vite dev preamble, so the CSP moved to the nginx and Caddy prod config.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `/ready` returns 503 with `database: error` | Postgres is not up yet, or the wrong URL. Run `docker compose ps` and check `PULSEOPS_DATABASE_URL` (host port **5433**). |
| `/ready` reports `queue: error` | ElasticMQ is not running, or the queues were never created. Rerun `docker compose run --rm migrate`. |
| Incidents never appear after loading a scenario | Check `docker compose logs relay worker`. A message picked up by a worker that was then killed reappears after the 60 s visibility timeout (by design). |
| Integration tests are skipped | Postgres is not reachable at `localhost:5433`. Run `docker compose up -d postgres elasticmq`. |
| `password authentication failed for pulseops_app` | The Postgres volume was initialised before `init-roles.sh` existed. Run `make reset`; this deletes local data. |
| `init-roles.sh: Permission denied` | Run `chmod +x deploy/postgres/init-roles.sh`, then `make reset`. |
| Dashboard login works but the API calls fail with CORS errors | `PULSEOPS_CORS_ORIGINS` must include the dashboard origin (`http://localhost:5173`). |
| Investigation `FAILED` with `credentials_missing` | `PULSEOPS_INVESTIGATOR_PROVIDER=anthropic` without `PULSEOPS_ANTHROPIC_API_KEY`. Set the key or switch back to `mock`. |
| Approve returns 409 `stale_proposal` | The incident changed after the proposal was made (for example, a new correlated event). Re-investigate. |
| `uv run` warns about `VIRTUAL_ENV` | Another virtualenv is active in the shell. It is harmless; `unset VIRTUAL_ENV` silences it. |
